# `tests/data/` — Tier 0 test fixtures

Small, hand-authored/generated fixtures committed directly to git. Fast
(no I/O beyond local files), deterministic, and don't require network
access, STAR, or samtools to regenerate.

- `annotation_test.1.gtf`, `.2.gtf`, `.3.gtf` — pre-existing minimal GTFs
  used by `test_annotation_parsers.py` / `test_annotation_utils.py` to
  exercise `GTFFeature`/`parse_gtf`/`merge_neighbors` in isolation.
- `synthetic/` — a hand-crafted mini single-cell dataset (GTF + BAM +
  whitelist + celltype TSV), generated by
  `../../../scripts/testdata/make_synthetic_fixtures.py`. Regenerate with:

  ```bash
  python scripts/testdata/make_synthetic_fixtures.py
  ```

  Unlike the annotation-only fixtures above, `synthetic/` provides a small
  but *complete* input set for `stellarscope assign`/`resolve` (BAM + GTF +
  whitelist + celltypes), with every scenario placed there on purpose so
  ground truth is known exactly:

  | File | Scenario covered |
  |---|---|
  | `alignment_mini.bam` (r1) | a plain unique read → sanity check for the happy path |
  | `alignment_mini.bam` (r2, 2 records) | a genuine 2-way tie between overlapping `locus1`/`locus2` → exercises `--reassign_mode` tie-breaking (`best_exclude`/`best_conf`/`best_random`/`best_average`) and EM ambiguity handling |
  | `alignment_mini.bam` (r1/r3/r4) | 3 records sharing one CB+UMI+position → UMI deduplication should collapse them to 1 |
  | `alignment_mini.bam` (r5) | a `GX`/`GN` tag over a TE locus → double-counting scenario for `stellarscope resolve`/`merge` |
  | `alignment_mini.bam` (r6) | unique read, second cell, second chromosome → independent-cell control |
  | `alignment_mini.bam` (r7) | on an off-whitelist barcode → `--whitelist` filtering |
  | `alignment_mini.bam` (r8) | falls outside any annotated locus → `__no_feature`/"other" bucket |
  | `whitelist_mini.txt` | 2 of the 3 barcodes used above (r7's is deliberately excluded) |
  | `celltypes_mini.tsv` | toy 2-celltype assignment, for `--pooling_mode celltype` |

  The BAM is intentionally **not** coordinate-sorted/indexed: `stellarscope
  assign` streams the alignment file assuming per-query-name contiguity
  (the same assumption `stellarscope cellsort` output satisfies) rather than
  doing indexed random access, and `synthetic/` is already built in that
  order.

  These are the right fixtures for new unit/characterization tests of
  `utils/model.py` (UMI dedup, `TelescopeLikelihood`, `Assigner`,
  `reassign`) — see the "Phase 3 gated on real test data" note in the perf/
  refactor roadmap. They are intentionally *not* meant to replace the
  `stellarscope/data/` package fixtures (see `../../data/README.md`), which
  test against real (if small) genomic sequence/annotation rather than a
  fully synthetic scenario.
